# Hoardini changes for the Windows port: 2026-10-17

**For:** the Hoardini Windows port (Rust).
**macOS baseline:** v0.5.7 (commit `8552f46`, "Installer: keep the extension working after the download is deleted").
**macOS result:** v0.5.8 (app/CLI/host), extension 0.4.5. Tag `v0.5.8` on GitHub.

Each entry below describes the **behavior** to reproduce, not the Swift code. The macOS version is the reference. Where something is Mac-specific, the entry says what the Windows equivalent should be. Numbering continues from [2026-10-15](2026-10-15.md).

## Changes

### 7. Videos not detected when the playlist is cached  (Fix: extension only)

**Problem:** On `portal.kismet.club` (a GoHighLevel "communities" site; videos come from `content.apisystem.tech/hls/...master.m3u8`), the popup sometimes listed nothing. Those playlists are served with `cache-control: public, max-age=3600, immutable`. The extension detected media in `chrome.webRequest.onHeadersReceived`, and Chrome **doesn't fire that event for responses served from the HTTP cache**. Opening the same video again within an hour (or a page that reused a cached playlist) left the list empty. A first visit worked, so it looked intermittent.

**New behavior (extension 0.4.5):**
- `background.js` detects media in `webRequest.onResponseStarted` (same filter and `responseHeaders` option). That event fires for cached and network responses alike. Classification is unchanged.
- When the popup opens, `popup.js` runs a small script in every frame of the tab (`allFrames: true`). It collects `.m3u8` URLs from `performance.getEntriesByType("resource")` plus the `src`/`currentSrc` of `<video>`/`<audio>`/`<source>` elements, and sends them to the background (`{type: "page-playlists", tabId, urls, origin}`). The background accepts only `http(s)` URLs whose path ends in `.m3u8`, skips blocked hosts (YouTube), caps it at 20, and adds them like detected ones (including fetching the master to list qualities). The referrer is the tab's origin. This catches what webRequest never reports at all: in-memory cache hits, and pages that loaded while the service worker wasn't running.

**Windows notes:** nothing to port. This is browser-extension code shared by both builds. Ship extension 0.4.5 with the Windows installer.

**How to verify:** open a Kismet post with a video and press play, download it, then reload the page and press play again. Before the fix the popup said "No media detected yet"; now it lists the HLS stream with its qualities (360p–1440p).

### 8. Install by dragging the app; the app sets itself up  (Feature: packaging + app)

**Problem:** The release zip contained the app, `bin/`, `extension/` and an `install.sh` the user had to run from Terminal. People expect to drag a `.app` into Applications (as with Renderooo), and updating meant running the script again.

**New behavior:**
- The release asset is now `Hoardini-<version>-macOS.zip` containing **only** `Hoardini.app`. The release notes include its SHA-256.
- The app bundle carries its helpers and the extension: `Contents/Helpers/hoardini`, `Contents/Helpers/hoardini-host`, `Contents/Resources/extension/`. (They go in `Helpers/`, not `MacOS/`, because the macOS file system ignores case and `hoardini` would overwrite the app executable `Hoardini`.)
- **On every launch** the app (`Sources/HoardiniApp/Setup.swift`):
  1. copies both helpers to `~/Library/Application Support/Hoardini/bin/` and the extension to `~/Library/Application Support/Hoardini/extension/`. Each copy is staged next to the target and swapped in, so a running host is never left half-written. It clears the quarantine flag on the copies, because the app quarantines files it writes (`LSFileQuarantineEnabled`), and macOS would block a quarantined host;
  2. reads the `key` from the installed extension's `manifest.json`, derives the extension ID from it (SHA-256 of the key's DER bytes, first 32 hex digits, `0–f` → `a–p`; currently `lllcaffncpkgndgbilnefakajeambdib`), and writes the host manifest `com.hoardini.host.json` for Chrome, plus Brave, Edge, Chromium, Vivaldi and **Arc** (`Arc/User Data/NativeMessagingHosts`) when that browser's support folder exists.
- On the **first** launch (a `extensionSetupShown` user default), it shows a dialog with the "Load unpacked" steps and puts the extension folder path on the clipboard. The dialog has a "Show Folder in Finder" button. The same dialog is in the menu bar menu as **Set Up Browser Extension…**. Loading an unpacked extension is the one step the app can't do for the user.
- Updating = drag in the new app, open it once (files are replaced in place), click Reload on the extension or restart the browser. The extension's folder path never changes, so the browser keeps working.
- The version now comes from the git tag in CI (`HOARDINI_VERSION`, used by `build-app.sh`; default `0.5.8`). `install-chrome.sh` (source builds) now just builds, installs and opens the app.

**Windows notes:**
- Same idea: on each start, the app copies `hoardini-host.exe` and the extension from its install folder to a permanent per-user folder (e.g. `%LOCALAPPDATA%\Hoardini\bin`, `%LOCALAPPDATA%\Hoardini\extension`), rewrites the host manifest JSON there, and (re)writes the per-browser registry keys listed in entry 6 (`HKCU\Software\<vendor>\NativeMessagingHosts\com.hoardini.host`, default value = manifest path). Doing it on every start makes "replace the exe and run it" a complete update.
- Replace the host exe by writing a new file and renaming it over the old one. If the old one is running (the browser keeps it open while the extension is connected), Windows refuses; fall back to a versioned file name, point the manifest at it, and delete stale copies later.
- Show the same one-time "Load unpacked" dialog with the folder path on the clipboard.
- There is no quarantine equivalent to clear; Mark-of-the-Web only applies to files that came from the internet, not ones the app copies itself.

**How to verify:** delete `~/Library/Application Support/Hoardini/{bin,extension}` and the `com.hoardini.host.json` files, unzip the release, drag `Hoardini.app` to Applications, open it. The folders and manifests come back, the dialog appears once, and "Download with Hoardini" reaches the app.
