## Changes

### 9. Only videos are taken from the browser  (Fix: extension only)

**Problem:** `chrome.downloads.onCreated` cancelled every http(s) download and handed it to Hoardini, including installers and archives. A `.dmg` downloaded this way came out broken.

**New behavior (extension 0.4.6):** a browser download is handed to Hoardini only when it is a video:
- MIME type `video/*` → video.
- Any other specific MIME type (`application/x-apple-diskimage`, `application/zip`, `audio/*`, …) → left to the browser.
- Generic MIME type (empty, `application/octet-stream`, `binary/octet-stream`, `application/force-download`, …) → decided by the extension of the file name, then of the URL path: `mp4 m4v webm mov mkv avi wmv flv mpg mpeg 3gp ogv` → video; any other extension → browser.
- Generic MIME type and no extension yet: the extension waits for `downloads.onChanged` to report the file name Chrome picked (from `Content-Disposition`) and decides then; if it is a video and still in progress, it is cancelled and handed over.

The right-click "Download with Hoardini" menu and the popup's detected-media list are unchanged; those are explicit choices.

**Linux notes:** nothing to port. Ship extension 0.4.6. (On Linux the same fix keeps `.AppImage`, `.deb`, `.rpm` and `.tar.gz` downloads in the browser.)

**How to verify:** with interception on, download a `.dmg` or `.zip`: it stays in the browser's download list and finishes normally. Download an `.mp4` link: it goes to Hoardini.
